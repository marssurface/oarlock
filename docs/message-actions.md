# 回答操作栏（消息底部工具条）

每条助手回答的正文下方有一行轻量操作：复制、评价、分享、固定、更多，右侧是「由 AI 生成」标注。用户消息没有这一行。

```
[复制] [有帮助] [没帮助] [分享] [固定] [更多]                    由 AI 生成
```

## 六个动作分别是什么

| 图标 | 名称 | 行为 | 状态 / 反馈 |
| --- | --- | --- | --- |
| 两个叠放的方框 | 复制 | 把这条回答的纯文本写入剪贴板 | 成功时图标短暂变成对勾（1.4s），失败弹 toast「复制失败」 |
| 大拇指向上 | 有帮助 | 标记这条回答有用 | 与「没帮助」互斥，再点一次取消；选中时图标与底色变强调色 |
| 大拇指向下 | 没帮助 | 标记这条回答没帮助 | 同上 |
| 向右上的箭头 | 分享 | 把「上一条用户提问（Markdown 引用块）+ 本条回答」复制到剪贴板 | toast「分享文本已复制」 |
| 锚 | 固定 | 在本地把这条回答钉住 / 取消钉住 | `aria-pressed` + 强调色；刷新后保留；toast「已固定这条回答」 |
| 三个点 | 更多 | 打开二级菜单：引用到输入框 / 复制为 Markdown / 导出为 .md | 同一时间只开一个菜单；点外部或按 Esc 关闭 |
| — | 由 AI 生成 | 固定的来源提示，鼠标悬停提示「内容由 AI 生成，请注意甄别」 | 常驻，靠右对齐 |

补充说明：

- **分享**没有服务端分享能力，所以落地为「复制一段可直接粘贴的 Markdown」：提问放在 `>` 引用块里，下面是回答正文；复制内容里不含操作栏和「由 AI 生成」。
- **固定**目前只是本机标记，不会回传给模型，也不会改变后续请求的上下文；用途是回看时快速识别「这条是要留着的」。
- **更多 → 引用到输入框**把回答前 140 个字符以 `> ` 引用块插到输入框开头并把焦点移回输入框，方便紧接着追问。
- **更多 → 复制为 Markdown** 输出 `**问：** … / **答：** …`；**导出为 .md** 下载 `dock-agent-answer-<hash>.md`。
- 「由 AI 生成」不是模型输出，是界面固定文案。

## 出现时机

- 只挂在**助手的文本回答**上，且正文非空；纯工具轮次（没有回答文本）不出现。
- 流式输出期间不出现，`turn-end`（或流结束 / 异常结束）时才挂载，避免回答还没写完就先露出操作栏。
- 操作栏是本轮内容的最后一行：正文 → 工具活动卡 / 执行过程 → 操作栏。
- 打开历史会话时走同一套渲染，顺序与实时一致；`liked` / `pinned` 状态会从本地存储恢复。

## 状态与持久化

存在浏览器的 `localStorage`，键名 `dock-message-state`：

```json
{
  "mw4jigv4-fbg6:7:a569uc": { "rating": "like", "pinned": true }
}
```

记录键为 `<sessionId>:<助手消息序号>:<内容哈希>`：

- 序号按当前会话里第几条助手文本回答计算，历史重放顺序固定，因此刷新后能对上；
- 内容哈希用 djb2，内容变了就是一条新记录，不会误用旧状态；
- 记录只在本地，不写入 `.agent/`，不上传，也不进入模型上下文；
- 清除方式：浏览器清站点数据，或执行 `localStorage.removeItem('dock-message-state')`。

## 交互与可访问性

- 按钮 26×26，图标 15px，继承 `--caption`；悬停变成 `--text` + 淡背景，选中态用 `--accent` 的 12% 底色。
- 每个按钮都有 `title` 和 `aria-label`；赞 / 踩 / 固定使用 `aria-pressed` 表达开关状态，取消后按钮标题同步变化（如「取消赞」）。
- 「更多」带 `aria-haspopup` / `aria-expanded`；菜单打开后点菜单外区域或按 Esc 关闭，Esc 不会顺带关掉设置面板或轨迹。
- 键盘焦点使用 `:focus-visible` 描边，不依赖悬停才能操作。
- 反馈统一用底部居中的 `#toast`（`role="status"`），1.8s 后淡出；`prefers-reduced-motion` 下取消位移动画。
- 复制优先 `navigator.clipboard.writeText`；不可用时回退到隐藏 textarea + `document.execCommand('copy')`。

## 布局与主题

- 操作栏是 `.inner` 的直接子元素，`margin-top: -6px` 抵消消息列表的 14px 间距，视觉上和正文贴得较近。
- 浅色 / 深色都只用 CSS 变量（`--caption` / `--text` / `--accent` / `--overlay-2` / `--line`），不写死颜色。
- 「由 AI 生成」用 `margin-left: auto` 贴右；窄屏（≤520px）下按钮仍在一行，不会横向溢出，多余空间由右侧标注让位。
- 二级菜单向上弹出（`bottom: 30px`），避免靠近输入框时被裁掉。

## 验证

```bash
npm test          # 59 项全部通过
npm run typecheck
npm run build     # 同步 dist/web/public
```

浏览器侧建议核对：

1. 实时一轮结束后操作栏出现在工具卡之后；
2. 复制成功时图标变勾 / 失败弹 toast；
3. 赞与踩互斥、再点取消；
4. 固定后刷新页面仍保持选中；
5. 更多菜单点外部、按 Esc 能关闭；
6. 浅色 / 深色、520px 宽度下按钮不换行、不横向溢出。

无头 Chrome 下剪贴板需要显式授权，可用 CDP 的 `Browser.grantPermissions` 授予 `clipboardReadWrite`、`clipboardSanitizedWrite` 后再断言复制结果。

## 暂未包含

- **重新生成**：需要服务端按消息重建回合，当前接口没有该能力，因此没有放进来。
- **评价回传**：赞 / 踩只存本机，不做统计上传。
- **分享链接 / 图片**：没有分享后端，只提供可粘贴的 Markdown 文本。
- **固定列表**：固定状态目前只影响这条消息自身的按钮和本地记录，还没有「已固定」聚合视图。
